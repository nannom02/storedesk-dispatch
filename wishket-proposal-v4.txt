자체 개발한 'AI Agent Orchestration Platform'을 기반으로, 고객의 업무 효율을 극대화할 수 있는 맞춤형 AI 시스템을 설계합니다. 컨설팅부터 설계, 개발에 이르는 전 과정에 시니어 전담 인력을 배치하며, 개발 도중에도 소통을 통해 최적화된 개선 방향을 제안합니다.

창고·입출고 운영 화면과 외부 데이터 검증, 역할별 권한, 처리 이력, 문서·알림 자동화를 설계한 경험을 이번 프로젝트의 상태 연결과 예외 처리에 적용하겠습니다.

▪ PM·기획: 현재 엑셀 장부와 실제 상담·입출고 절차를 기준으로 상태, 책임자, 예외, 승인 기준 확정
▪ 프론트엔드: 관리자 PC와 현장 모바일에서 고객·창고·입출고·운송 작업을 같은 데이터로 처리하는 반응형 화면 구현
▪ 백엔드·DB: 고객·계약·컨테이너·운송업체·작업지시·입출고·결제·문서·알림 원장과 변경 이력 구현
▪ 외부 연동: 기존 챗봇, 알림톡·문자, 결제·세금계산서 연동 규격과 실패 재처리 흐름 구현
▪ QA·배포: 데이터 이관 검증, 역할별 시나리오 검수, 배포·백업·복구·인수인계 문서화

모든 주요 상태와 권한은 화면 설계서, ERD, API 명세, 검수 시나리오에 같은 용어로 기록합니다. 주간 확인에서 승인된 화면과 규칙을 기준선으로 관리하고, 변경 요청은 영향 범위와 검수 결과를 함께 남기겠습니다.

【2. 핵심 구현 제안】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 외부 운송업체 배정과 작업지시를 하나의 흐름으로 관리합니다
운송업체명, 담당자, 연락처, 사업자번호, 서비스 지역, 비고, 수행 건수와 정시율을 기준정보로 관리합니다. 입출고 건에서 업체를 배정하고 변경 시 사유·처리자·시각을 이력으로 남깁니다. 출고 건은 기존 입고 운송업체를 먼저 조회할 수 있게 하되 일정이 맞지 않으면 다른 업체로 재배정할 수 있습니다.

작업지시는 고객명·연락처, 상담 메모, 희망 날짜·시각, 출발지·도착지, 수취인·연락처, 엘리베이터 여부 중 전달할 항목을 선택해 운영팀·창고팀·운송업체에 한 번에 발송합니다. 운송업체는 별도 로그인 없이 전달받은 정보만 읽을 수 있고 수정 권한은 주지 않습니다. 운송비와 리프트 비용은 건별로 기록하되 운송업체 정산·매입 세금계산서는 이번 범위에서 제외합니다.

■ 출고완료를 업무의 최종 상태로 연결합니다
입고는 상담진행중·예약완료·운송자매칭완료·입고완료, 출고는 출고예약·운송자매칭완료·출고완료로 관리합니다. 출고완료 시 고객은 보관종료, 계약은 만료, 컨테이너는 사용 가능으로 함께 변경합니다. 담당자가 세 화면을 각각 수정하지 않아도 되며, 처리자·처리 시각·변경 이력이 같은 입출고 번호로 남습니다.

■ 기존 엑셀을 검증 가능한 원장으로 옮깁니다
계약 장부 662행과 출고 장부 1,020행을 원본 보존 상태로 검증하고, 완전 중복 25건, 연락처 분리, 날짜 형식, 창고번호 표기, 출고 장부의 단일 영문자 날짜 값을 규칙별로 분류합니다. 자동 보정한 값과 사람이 확인할 값을 구분하고 시트별 건수·금액 합계·오류 유형·수정 이력을 이관 보고서로 남깁니다.

■ 문서·사진·알림의 보존 기준을 운영 화면에 반영합니다
계약 내용을 복사하고 첨부 사진을 묶어 내려받을 수 있게 하며, 입고 사진은 고객 열람, 출고 사진은 내부 전용을 기본값으로 둡니다. 출고 완료 계약 3년, 출고 사진 1개월 보존을 초기안으로 제시하되 착수 시 확정한 정책을 환경 설정에서 관리합니다. 만료 전 안내와 당일 미입금 안내는 대상·문구·발송·실패 재처리 이력까지 확인할 수 있게 합니다.

【4. 제안 기술 스택】

▪ 파일 보관: Supabase Storage — 계약서·안내문·입출고 사진을 계약과 연결하고 접근 범위·보존기간 적용

공고에 지정 기술이 없어 운영 인력 부담, 모바일 대응, 데이터·파일 권한, 배포·복구 요구를 기준으로 제안드리는 구성입니다. 착수 시 기존 소스·DB·도메인·외부 연동 규격과 발주사 계정 정책을 확인한 뒤 최종 확정하겠습니다.

이번 제안용 프로토타입은 위시켓 포트폴리오 미등록 상태이므로 선택 목록에서 제외합니다. 기존 포트폴리오는 제출 직전 최신 등록 Pool을 다시 확인한 뒤 최대 3건만 별도로 선택합니다.


═══════════════════════════════════════════════════════════
위시켓 입력란 3 — 관련 포트폴리오 설명
═══════════════════════════════════════════════════════════

입력란 2의 포트폴리오를 확정한 뒤 선택한 자료만 기준으로 2,000자 이내 원고를 작성합니다. 미등록 프로토타입을 실제 수행 사례나 선택 가능한 포트폴리오로 표기하지 않습니다.

[변경 사항]
- v4 신규 작성. 재등록 공고에서 추가된 외부 운송업체 원장·배정·재배정·비용·3자 작업지시와 출고완료 상태 연동을 최우선 흐름으로 재작성.
- 기존 공고의 견적 계산·예약금 수납은 외부 절차, 운송업체 정산·매입 세금계산서는 후속 확장으로 범위를 분리.
- 첨부 문서의 계약 장부 662행, 출고 장부 1,020행, 완전 중복 25건과 정제·검증 조건을 반영.
- 신규 공개 주소 https://storedesk-dispatch.vercel.app 반영.

[프로토타입 상태]
- 기존 프로젝트 기반 개정: 이전 제안용 프로토타입의 운영 범위를 보존하고 이번 재등록 공고 차이를 추가 구현.
- 배포 상태: 공개 운영 주소 접속 및 HTTP 200 확인.
- 포트폴리오 상태: 미등록. 위시켓 선택 목록에는 포함하지 않음.
