본 프로젝트의 핵심을 "은행 거래내역과 계약 원장을 자동으로 맞춰 두고, 담당자가 예외 건만 판정하면 만료일·연체·청구·안내 발송이 하나의 운영 체계로 이어지게 하는 것"으로 이해했습니다.

그래서 프로토타입도 대시보드가 아니라 입금 대조부터 만들었습니다. 이 시스템의 성패는 화면 수가 아니라 "매달 몇 건이 예외로 남는가"에서 갈립니다. 자동 대조가 절반만 맞으면 담당자는 결국 전체를 다시 눈으로 보게 되고, 시스템은 쓰이지 않습니다. 프로토타입에서 9건 중 4건을 자동 매칭하고 남은 5건만 판정하도록 만든 이유이며, 한 번 사람이 확인한 입금자명을 고객의 등록 입금자명으로 저장해 다음 달 예외를 줄이는 구조를 핵심으로 잡은 이유입니다.

【1. 팀 소개 및 수행 체계】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

저희는 5명의 개발·컨설팅 전문 인력으로 구성된 시니어 중심의 IT 파트너입니다. 대기업 S사 프로젝트 경험을 바탕으로 MES, PLM, SCM 구축은 물론 평가·시뮬레이션, 견적 시스템, 보건/의료 및 간호 교육 분야, 그리고 AI Agent 개발에 이르기까지 다양한 도메인에서 프로젝트를 수행하고 있습니다.

자체 개발한 'AI Agent Orchestration Platform'을 기반으로, 고객의 업무 효율을 극대화할 수 있는 맞춤형 AI 시스템을 설계합니다. 컨설팅부터 설계, 개발에 이르는 전 과정에 시니어 전담 인력을 배치하며, 개발 도중에도 소통을 통해 최적화된 개선 방향을 제안합니다.

도메인 규칙을 코드에서 분리해 운영팀이 직접 단가와 기준을 바꾸게 만들고, 자동 산출 결과를 사람이 최종 확정하며 그 판단 근거와 이력을 남기는 구조를 여러 프로젝트에서 실제로 구축해 왔습니다. 이번 입금 대조·연체 판정이 정확히 그 구조입니다.

▪ PM·기획: 실무 담당자 1명과의 요구사항 확정, 주 1회 오프라인 미팅 운영, 입금 대조·연체·정산 규칙 정의서 작성
▪ 프론트엔드: 관리자 웹 16개 업무 화면과 모바일 반응형(입출고 확인·고객 조회·창고번호 입력), 고객 안내문 열람 페이지
▪ 백엔드·DB: 고객·계약·컨테이너·입금 거래·발송 이력 스키마, 자동 대조 규칙 엔진, 등록 입금자명 저장, 권한·처리 이력
▪ 외부 연동: 결제선생, 센드빌, 카카오 알림톡·문자, 기존 챗봇 연계와 실패 재처리
▪ QA·배포: 클라우드 구성과 배포·롤백, 매일 1회 암호화 백업, 보안 점검 결과서

개발자가 없는 조직에서 가장 위험한 것은 "말로 확인하고 넘어간 요구사항"입니다. 저희는 상태·권한·API 명세를 문서가 아니라 작동하는 화면으로 먼저 보여 드립니다. 계약 후 실제 엑셀 장부와 발송 문구를 놓고 2차 프로토타입을 만들어 최종 확인을 받은 뒤에 본 개발을 시작하고, 개발 주소는 기간 내내 열어 두어 언제든 직접 확인하실 수 있게 합니다.

【2. 핵심 구현 제안】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 자동 대조가 예외를 얼마나 줄이는지가 이 프로젝트의 성패입니다
계약자명 일치, 고객별 등록 입금자명 일치, 금액 일치를 순서대로 적용해 자동 확정합니다. 자동 확정할 수 없는 건만 네 가지로 분류합니다. 같은 이름이 둘 이상인 동명이인, 등록되지 않은 입금자명, 월 이용료에 미달하는 분할 입금, 연결할 계약이 없는 입금입니다. 분류마다 판정 근거를 문장으로 남겨 담당자가 무엇을 비교해야 하는지 바로 알 수 있게 했습니다. 동명이인은 후보 계약의 월 이용료·만료일·최근 입금을 나란히 놓고 비교합니다.

■ 사람이 한 번 확인한 입금자명은 시스템이 기억합니다
수동 연결한 입금자명을 해당 고객의 등록 입금자명으로 저장하고, 확인 출처와 시각을 등록 입금자명 원장에 남깁니다. 다음 업로드부터 같은 이름은 자동 매칭됩니다. 대표자 개인 명의 이체나 법인 담당자 명의 이체처럼 매달 반복되는 예외가 이 방식으로 사라집니다. 분할 입금은 같은 입금자명 건을 합산해 배수만큼 만료일을 연장하고, 계약 상태를 `만료`에서 `정상`으로 되돌립니다.

■ 판정 결과가 계약 원장 하나로 이어집니다
입금을 연결하면 계약 만료일이 다시 계산되고, 연체 상태와 미수금, 만료 예정 D-day, 발송 대상, 처리 이력이 같은 원장에서 함께 바뀝니다. 프로토타입에서 예외 5건을 판정하면 대시보드의 미매칭 5건이 1건으로, 만료 예정 5건이 3건으로 줄어드는 것을 직접 확인하실 수 있습니다. 안내만 뜨고 데이터는 그대로인 화면은 만들지 않았습니다.

■ 외부 연동은 실패를 다루는 방식까지 화면에 있습니다
결제선생 카드 결제 요청·승인, 미수 → 통장 입금 확인 → 입금 완료 2단계, 센드빌 세금계산서 일괄 발행, 카카오 알림톡 발송과 실패 시 문자 재발송을 연결 상태·처리 결과·실패 사유·재시도 이력이 보이는 형태로 구현했습니다. 운영 키, 공동인증서, 발신번호, 챗봇 연동 규격서는 발주사 준비 사항으로 분리했습니다.

【3. 수행 및 산출물 계획】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

▪ 1주차 · 인수·정책 확정: 엑셀 장부 원본과 최근 은행 거래내역 확인, 창고 3개소 기준정보, 연체료·정산 규칙과 발송 시점 확정, 외부 연동 계정 준비 일정 합의
▪ 2~3주차 · UX·설계: 16개 기능군 화면 흐름·정보구조, ERD, API, 상태·권한 명세, 입금 대조·연체·정산 규칙 정의서, 외부 연동 규격서
▪ 4주차 · 2차 프로토타입 확인: 실제 서식과 확정 규칙을 반영한 작동형 화면을 역할별로 함께 눌러 보고 본 개발 착수 승인
▪ 5~13주차 · 통합 개발: 고객·계약·컨테이너, 입출고, 입금 대조·미매칭·연체·정산, 결제·세금계산서, 안내문·발송, 챗봇 연계, 권한·이력, 모바일 반응형
▪ 14~15주차 · 통합 검수: 실제 거래내역 표본으로 대조 정확도 검증, 예외 시나리오, 권한·보안 점검, 데이터 이관 검증
▪ 16~17주차 · 시범운영·인계: 실제 업무 병행 운영, 사용자 교육, 소스·DB 스키마·배포/운영 매뉴얼·보안 점검 결과서 인계

산출물은 공고에 적어 주신 요구사항 정의서, 화면 설계서, 입금 대조·연체·정산 규칙 정의서와 외부 연동 규격서, 전체 소스코드(발주사 소유 저장소), DB 스키마, 배포·운영 매뉴얼, 보안 점검 결과서를 그대로 제출합니다. 오픈 후 3개월 하자보수를 포함합니다.

【4. 제안 기술 스택】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

▪ 관리자 웹·모바일 반응형: React, TypeScript — 화면 하나로 PC와 휴대폰을 모두 지원해 현장용 앱을 따로 만들지 않아도 됩니다
▪ 서버·API: Vercel 서버리스 — 서버 장비 구매와 서버 관리 인력 없이 운영됩니다
▪ 인증·권한·데이터베이스: Supabase Auth + PostgreSQL — 관리자/최고관리자 등급, 로그인 실패 제한, 자동 로그아웃, 기능별 권한을 표준 기능으로 처리합니다
▪ 파일 보관: Supabase Storage — 사업자등록증, 계약서, 안내문 PDF, 현장 사진을 계약 건에 묶어 접근 권한과 함께 보관합니다
▪ 외부 연동: 결제선생, 센드빌, 카카오 알림톡·문자, 기존 챗봇(서버 분리 유지)
▪ 인프라·보안: 발주사 명의 계정, TLS, 사설 VPN, 매일 1회 암호화 백업과 시점 복구, ERP 화면 외 접근 차단, 관리자 접근 IP 허용, 배포 이력과 즉시 롤백

공고에 지정 기술이 없어 요구사항과 운영 조건을 근거로 제안드리는 안입니다. 사내에 전산 담당자가 안 계신 점을 가장 크게 봤습니다. 장비를 사서 직접 관리하는 구성은 초기 비용뿐 아니라 서버 패치·인증서 갱신·백업 확인을 계속 누군가 해야 합니다. 위 조합은 백업·복구·모니터링이 기본으로 포함되고, 계정이 발주사 명의라 계약이 끝나도 소스와 데이터가 그대로 남습니다. 사설 VPN은 기본 보안 범위에 포함하고, 접속 인원·기기 수와 기존 네트워크 환경을 확인해 계정·인증서 발급·폐기, 기기 설치 지원과 운영 비용을 착수 미팅에서 구체화하겠습니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【5. RFP 관련 실제 수행 경험】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

▪ 도메인 규칙을 코드에서 분리하고 그 규칙으로 금액을 자동 산출한 뒤 문서를 자동 발행하는 시스템을 구축했습니다. 운영팀이 단가를 직접 바꾸면 계산과 문서가 함께 바뀌는 구조로, 이번 연체료 규칙 변경과 계약 안내문·세부 내역서 자동 생성에 그대로 적용됩니다.
▪ 자동 처리 결과를 스키마로 검증하고, 검증에 걸린 건만 사람이 최종 확정하며, 세션·배치·호출 단위로 전 과정을 추적하는 시스템을 운영해 왔습니다. 이번 입금 대조의 "자동 확정 → 예외만 판정 → 처리 이력" 구조와 같습니다.
▪ 외부 데이터를 주기적으로 받아 검증하고, 임계치를 넘으면 알림을 보내며, 역할별 권한과 변경 이력을 남기는 창고·입출고 운영 화면을 설계했습니다. 이번 미매칭 상단 알림, 미확인 알림 에스컬레이션, 삭제 권한 제한에 적용할 수 있습니다.

【6. 보안·인수인계 및 착수 전 확인】

▪ 고객 약 1,500명의 이름·연락처·계약 정보가 들어오므로 접근을 역할로 제한하고, 조회·수정·삭제 시도를 모두 처리 이력에 남깁니다. 삭제는 최고관리자만 실행할 수 있고 권한이 없는 시도도 기록됩니다.
▪ 기존 엑셀 장부는 사본으로만 작업합니다. 연락처 형식, 계약 기간 역전, 컨테이너 중복 배정, 입금자명 공백 같은 오류를 규칙으로 먼저 걸러 내고, 운영과 분리된 검증 환경에 올려 화면에서 직접 확인하신 뒤 운영에 반영합니다.
▪ 발주사에서 확정해 주셔야 할 항목: 연체료율과 유예 일수, 연체 판정·안내 발송 시각, 안내문 양식(개인/법인/법원)의 실제 문구, 현장 사진 보관 기간
▪ 발주사에서 준비해 주셔야 할 항목: 결제선생 운영 키, 센드빌 공동인증서, 알림톡 채널과 문자 발신번호 사전등록, 기존 챗봇 연동 규격서, 클라우드·도메인 계정 명의

공고에서 아직 정하지 않으셨다고 하신 네 항목은 프로토타입의 `착수 전 결정사항` 화면에 제안사 권장안과 함께 정리해 두었습니다. 현장 사진·기사 열람 링크는 기본 기능의 이번 범위 포함을, 입금표·거래명세표는 프로토타입의 안내문·세부 내역서 흐름을 바탕으로 한 시스템 발행을 권장드립니다. 수정 승인 절차는 권한 등급과 처리 이력으로 간소화하고, 매일 자동 점검은 미매칭·발송 실패·연동 실패·만료 예정 예외 목록으로 제공하는 안을 제시했습니다. 예약 발송은 선택 발송으로 시작하되, 이번 범위에 포함하실 경우 단계 기준과 문구를 착수 미팅에서 정합니다. 각 권장안을 출발점으로 범위·우선순위·단가를 함께 조율하겠습니다.

지금 보고 계신 프로토타입은 완성품이 아니라 협의의 출발점입니다. 계약 후 실제 자료를 반영한 2차 프로토타입을 최종 확인받고 본 개발을 시작하며, 종료 시 소스·DB 스키마·운영 문서와 함께 운영 지식을 인계합니다.

■ 1. [Prototype] 컨테이너 창고 입금·계약·정산 통합 운영 ERP
본 공고의 요구사항을 기준으로 제작하고 위시켓에 등록한 제안용 프로토타입입니다. 은행 거래내역을 계약자명·등록 입금자명으로 자동 대조하고 동명이인·미등록명·분할 입금 등 예외만 담당자가 판정하면 계약 만료일, 연체·청구, 안내 발송과 처리 이력이 함께 갱신되는 흐름을 실제 화면으로 연결했습니다. 운영·회계 정산·창고 현장·최고관리자 권한과 기존 엑셀 장부 이관 절차도 확인할 수 있습니다. 실제 납품 사례가 아니라 이번 프로젝트의 이해도와 구현 방향을 검토하기 위한 자료입니다.

■ 2. 온천·지하수 개발 견적 시뮬레이션 - 견적 산출 및 제안서 자동 발행 시스템
실제 수행한 프로젝트입니다. 여러 비용 모듈의 도메인 규칙을 코드에서 분리해 운영팀이 단가와 기준을 직접 바꾸면 계산 결과가 함께 바뀌도록 만들었고, 산출된 결과를 그대로 제안서 문서로 자동 변환해 미리보기·저장·인쇄까지 연결했습니다. 이번 프로젝트의 연체료 계산 규칙과 계약 안내문·세부 내역서 자동 생성이 같은 구조입니다. 환경 설정에서 연체료율과 유예 일수를 바꾸면 연체·정산 금액과 미수금 집계가 즉시 다시 계산되고, 그 값이 그대로 안내문 청구 내역에 들어가도록 설계할 수 있습니다. 창고별·개인/법인/법원으로 갈리는 양식 분기도 같은 템플릿 분리 방식으로 처리합니다.

■ 3. [AI Agent Platform] AI 문서 생성·검증 AI 자동 평가 System
실제 수행한 프로젝트입니다. 자동으로 만들어진 결과를 스키마로 검증하고, 검증에 걸리거나 확신이 없는 건만 담당자가 최종 확정하며, 세션·배치·호출 단위로 전 과정을 추적할 수 있게 운영했습니다. 이번 입금 대조가 정확히 같은 구조입니다. 계약자명·등록 입금자명·금액 규칙으로 자동 확정하고, 판정할 수 없는 건만 검토 목록으로 넘기며, 배치 단위로 자동·수동·보류 건수와 처리자·처리 시각을 남깁니다. 자동 처리 비율을 어디까지 올릴 수 있고 어디부터 사람이 봐야 하는지 판단해 본 경험을 그대로 적용할 수 있습니다.

※ 전용 프로토타입으로 이번 프로젝트의 역할·업무·상태 연결을 먼저 보여 드리고, 두 실제 수행 사례로 "규칙 기반 자동 산출과 문서 발행", "자동 확정 후 예외 판정과 전 과정 추적" 구조를 실제로 구축한 경험을 뒷받침합니다.
